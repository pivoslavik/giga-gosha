# Giga Gosha

- Проект команды из двух человек. Цель — помочь соискателю подбирать вакансии и откликаться на них по резюме.
- Все три сервиса написаны на TypeScript и организованы как npm workspaces: `services/bot` — Telegram-бот `@gigagoshabot`, `services/parser` — получение вакансий, `services/ml` — подбор по резюме. Общая HTTP-проверка процессов расположена в `packages/runtime`.
- Для MVP выбраны PostgreSQL для данных и Kafka для передачи заданий на подбор в ML-воркер. Планируемая гарантия — доставка как минимум один раз с сохранением единственного результата на задание. Состояние откликов и расписание отправки принадлежат приложению.
- Первый пользователь ищет IT-стажировки и junior-позиции в разработке и QA. Учитывайте несколько версий резюме, график и обязанности. У вакансии должна быть прямая ссылка на объявление.
- Первая площадка — hh.ru. Декабрьское демо охватывает обе площадки. Приложение на dev.hh.ru пока не зарегистрировано. Первый шаг — заявка на доступ и проверка возможностей приложения соискателя.
- Бот собирает настройки до начала поиска. При явно указанном графике учитывайте предпочтения пользователя. Отсутствие графика не влияет на решение. Удалёнка проходит географический фильтр, для гибрида учитывайте город и готовность к переезду.
- При подборе стажировок и junior-позиций не используйте требуемый коммерческий стаж как фильтр. Сопоставляйте обязанности с выбранными направлениями и содержанием каждой версии резюме. Первая пара для проверки — Go backend и Java backend.
- Для hh.ru планируется использовать резюме из профиля соискателя. Для Хабр Карьеры бот принимает PDF. По опыту команды, каждый гостевой отклик требует reCAPTCHA. В этом сценарии пользователь завершает отправку на площадке. Открытие ссылки не подтверждает отправку. В примере успешного ответа есть поля `success` и `response.hasResponse`.
- Целевой режим — автоотклик по настройкам и согласование спорных случаев. Близкие резюме одного направления (Go и Java backend) бот выбирает сам. При неоднозначном выборе между разными ролями (DS и Python backend) запрашивает решение.
- Первый поиск охватывает последние семь дней. Затем каждые 10 минут в окне 09:00–19:00 по Москве бот пополняет очередь пользователя. Утром поиск охватывает публикации с последней успешной проверки.
- При включённом авторежиме бот раз в час в рабочее окно отправляет отклики из очереди с учётом релевантности и свежести вакансий. В Telegram выводит случаи, требующие участия пользователя. Если таких случаев нет, уведомление не требуется. Числовой дневной лимит не задан.
- Бот готовит отдельное сопроводительное письмо для каждой вакансии на основе выбранного резюме. Если работодатель запрашивает сведения, отсутствующие в резюме и настройках, бот обращается к пользователю.
- Демонстрация MVP запланирована на середину декабря 2026 года и начинается с первичной настройки бота. Планируется недорогой VPS на месяц. Отчёт о вкладе участников — еженедельно.
- Группируйте код по функциям продукта. Обработчики Telegram вызывают прикладную логику. Доступ к данным и внешним площадкам держите отдельно от неё.
- У каждого сервиса свой Dockerfile. Для локального Compose копируйте `.env.example` в `.env`. При подключении Kafka-клиента приложение будет создавать топик из `KAFKA_MATCHING_TOPIC`. Настройки локального KRaft-брокера находятся в `infra/kafka/server.properties`.
- Фиксируйте точные версии Node.js, npm и пакетов, сохраняйте `package-lock.json`, указывайте точные теги версий Docker-образов и GitHub Actions. Для всех workspaces действуют общие проверки `npm run lint` и `npm run typecheck`.
- Проверяйте значимую бизнес-логику тестами. Обновляйте этот файл при изменении архитектуры и рабочих договорённостей.
